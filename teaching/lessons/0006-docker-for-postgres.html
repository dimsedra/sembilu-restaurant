Docker: The Apartment for Your Database

Lesson 6 · Running PostgreSQL without installing it directly on your computer.

🏢 Imagine a furnished apartment building. Each apartment comes with everything a specific service needs — its own furniture, its own plumbing, its own rules. You don't install a "kitchen" directly into your house; you just rent an apartment that already has one. When you're done, you return the keys. No trace left behind.

That's Docker. It runs containers — self-contained environments that have everything a piece of software needs to run. Want PostgreSQL? You don't install it on your computer. You just tell Docker: "rent the PostgreSQL apartment." It downloads a pre-made apartment (called an image) and runs it.

Why Docker instead of installing directly?

Installing PostgreSQL directlyDocker
Runs as a Windows service — always onRuns only when you ask it to
Uninstall leaves files behindOne command, completely gone
Different version? Uninstall and reinstallDifferent version = different container
If you mess up the config, hard to resetDelete the container, create a new one in seconds

For learning, Docker is perfect. You will break things. Being able to trash the database and start fresh with one command is liberating.

The one command

Open PowerShell and run this:

docker run -d `
  --name sembilu-db `
  -e POSTGRES_PASSWORD=sembilu `
  -e POSTGRES_DB=sembilu `
  -p 5432:5432 `
  postgres:17

Let's break down what each piece does:

docker runCreate and start a new container
-d"Detached" — run in the background, don't take over my terminal
--name sembilu-dbGive this container a name so we can refer to it later
-e POSTGRES_PASSWORD=sembiluSet an environment variable inside the container — this one sets the database password
-e POSTGRES_DB=sembiluCreate a database named "sembilu" automatically on startup
-p 5432:5432"Port mapping" — connect port 5432 on your computer to port 5432 inside the container (PostgreSQL's default port)
postgres:17Which image to use — PostgreSQL version 17, the official one

What these terms mean

Image
A blueprint. The postgres:17 image is a pre-made blueprint of PostgreSQL 17 with Ubuntu, ready to run. You don't build it — you download it from Docker Hub (like an app store for containers).
Container
An actual running instance of an image. Like "an apartment built from the blueprint." You can have multiple containers from the same image (multiple apartments from the same blueprint).
Port mapping (-p)
The container has its own little network inside. Port mapping makes a port inside the container available on your computer. Without this, your Express server couldn't reach the database.
Volume
Storage that survives even if you delete the container. We're not using one yet — meaning if you delete the container, all data goes with it. That's fine for learning. We'll add one later.

Useful commands after that

# See running containers
docker ps

# Stop the database
docker stop sembilu-db

# Start it again (data is still there)
docker start sembilu-db

# See its logs (what's happening inside)
docker logs sembilu-db

# Delete it completely (⚠️ ALL DATA GONE)
docker rm -f sembilu-db

What about .env?

Once the container is running, create a .env file at the project root:

DATABASE_URL=postgres://postgres:sembilu@localhost:5432/sembilu

This is what Express + knex will read to connect to the database.

Try it now: Run the docker run command above in PowerShell. Then run docker ps to confirm it's running. After that, we'll run our first migration together.
