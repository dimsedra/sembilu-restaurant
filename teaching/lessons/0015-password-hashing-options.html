Lesson 15: Password Hashing for Staff Auth

Lesson 15 · Comparing bcryptjs, node:crypto (scrypt), and argon2 for Sembilu

🔐 Scenario at SEMBILU: Chef Budi and Waiter Wati log into the staff dashboard using passwords like sambal123. If an attacker breaches the database, plain-text passwords would give them access to staff accounts. We must store cryptographic hashes so even database admins cannot read raw passwords.

1. The Core Concept: Slow Hashing & Salting

Unlike fast hashing algorithms (like MD5 or SHA-256 designed to checksum files in milliseconds), password hashing algorithms are deliberately slow.

  • Salting: Adding a random string of bytes to each password before hashing so identical passwords produce totally different hashes. This prevents rainbow table lookup attacks.
  • Adaptive Cost (Work Factor): A knob you turn to force the server to take ~100ms per hash. This makes brute-force guessing millions of passwords astronomically expensive for hackers.

2. The Three Contenders

Option 1: bcrypt (via bcryptjs)

Created in 1999 based on the Blowfish cipher. It has been the undisputed standard in Node.js for over a decade.

Why bcryptjs instead of bcrypt?
Standard bcrypt compiles native C++ code using node-gyp. On Windows machines without C++ build tools, installation often throws build errors. bcryptjs is a 100% pure JavaScript implementation — it works identically on every OS without any native compiler.
  • Pros: Extremely easy to use (bcrypt.hash(pwd, 10) and bcrypt.compare(pwd, hash)), ubiquitous in Express tutorials, zero native build issues on Windows.
  • Cons: Truncates passwords longer than 72 bytes (rarely an issue for human passwords).
import bcrypt from 'bcryptjs';

// Hash password on staff creation
const hash = await bcrypt.hash('sambal123', 10);

// Verify password on login
const isValid = await bcrypt.compare('sambal123', hash);

Option 2: node:crypto (Built-in scrypt)

Node.js has a built-in crypto module that includes scrypt — a memory-hard password hashing algorithm standardized in 2012.

  • Pros: Zero npm dependencies. It comes built into Node.js, meaning zero security vulnerabilities from external packages and zero install steps.
  • Cons: Requires slightly more boilerplate code (formatting salt and hash into a string, wrapping callback in a Promise).
import crypto from 'node:crypto';
import { promisify } from 'node:util';

const scrypt = promisify(crypto.scrypt);

// Hash password with random salt
const salt = crypto.randomBytes(16).toString('hex');
const derivedKey = (await scrypt('sambal123', salt, 64)) as Buffer;
const storedHash = `${salt}:${derivedKey.toString('hex')}`;

// Verify password
const [saltPart, keyPart] = storedHash.split(':');
const keyBuffer = Buffer.from(keyPart, 'hex');
const testKey = (await scrypt('inputPassword', saltPart, 64)) as Buffer;
const match = crypto.timingSafeEqual(keyBuffer, testKey);

Option 3: argon2

The winner of the international Password Hashing Competition in 2015. Argon2 (specifically argon2id) is considered the modern state-of-the-art gold standard in cryptography.

  • Pros: Resists GPU/ASIC hardware cracking and side-channel timing attacks better than any older algorithm.
  • Cons: Requires native C++ compilation (node-gyp), which can cause install failures on some Windows developer setups.
import argon2 from 'argon2';

const hash = await argon2.hash('sambal123');
const isValid = await argon2.verify(hash, 'sambal123');

4. Summary Recommendation

For learning & practical Windows DX in Sembilu:
• bcryptjs is the most intuitive and hassle-free choice. It gives you the exact standard API (hash and compare) used in 95% of Express apps without any Windows build headaches.
• node:crypto is awesome if you specifically want to master Node's built-in standard library without external dependencies.
