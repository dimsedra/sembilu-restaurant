Lesson 0021 · Sembilu Operating System · Informed Context & Knowledge

In this lesson, we establish the Informed Context and Informed Knowledge behind T7 (Staff Order Management / KDS). You'll see how kitchen orders move smoothly from the table to the chef's screen and back to the waiter's view.

🏛️ 1. Informed Context: The Kitchen Screen Flow

How Orders Flow at Sembilu Tegal

When a customer orders 2x Ayam Goreng and 1x Sambal Terasi at Table 4:

  1. The order appears on the **Kitchen Display System (KDS)** screen as pending.
  2. Chef Budi taps "Start Cooking" on the Ayam Goreng ➔ Status becomes cooking.
  3. When Chef Budi finishes frying, he taps "Done" ➔ Status becomes done.
  4. When all dishes for Table 4 are finished, the parent order status automatically becomes done, alerting Waiter Wati to serve the food!

Operational Guardrails We Established (ADR-0005)

  • Strict State Machine: Dishes must move forward (pending ➔ cooking ➔ done). A chef cannot accidentally reset a cooked dish back to pending.
  • Branch Isolation: Staff at Tegal can only see orders at Tegal (branch_id: 1). Attempting to edit orders at Jakarta returns 403 Forbidden.
  • Automatic Parent Order Syncing: Chefs don't have to double-click table status buttons — when the last dish is marked done, the table order automatically becomes done.

📚 2. Beginner's Code Glossary

PATCH
An HTTP method used for updating specific fields of an existing resource (e.g. updating item status without re-sending the whole order).
state machine
A logic pattern that enforces valid status transitions (e.g. pending ➔ cooking ➔ done) and blocks invalid state jumps.
branch scoping
Filtering query results automatically by req.staff.branch_id so users only see their own branch's data.
propagation
Automatically updating a parent record (the table order) when child records (the dishes) reach a milestone.

🧩 3. Informed Knowledge: Implementation Architecture

1. Fetching Branch Orders (GET /api/staff/orders)

// Protected by requireStaffAuth middleware
const targetBranch = (req.staff.role === "manager" && req.query.branch_id)
  ? Number(req.query.branch_id)
  : req.staff.branch_id;

const orders = await db("orders")
  .where({ branch_id: targetBranch })
  .orderBy("created_at", "asc");
  • req.staff.branch_id: Extracts the authenticated staff member's branch from their JWT token.
  • req.staff.role === "manager": Allows managers to optionally inspect other branches via ?branch_id=X.

2. Updating Item Status (PATCH /api/staff/orders/:id/items/:itemId)

const VALID_TRANSITIONS: Record = {
  pending: "cooking",
  cooking: "done",
};

if (VALID_TRANSITIONS[currentItem.status] !== newStatus) {
  return res.status(400).json({ error: `Invalid status transition from ${currentItem.status} to ${newStatus}` });
}
  • VALID_TRANSITIONS: Enforces our strict forward state machine! pending can only become cooking, and cooking can only become done.
