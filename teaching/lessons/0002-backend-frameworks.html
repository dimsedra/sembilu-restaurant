The Backend Chef

Lesson 2 · Comparing four ways to build the engine behind Sembilu.

Think of the backend as the kitchen behind the wall. The frontend (what customers and waiters see) is the dining room. The backend is where the actual work happens: storing orders, checking if a table is free, pushing "order is ready" to the waiter's screen.

We need a head chef — a TypeScript framework — to organize this kitchen. Four candidates, each with a different style.

The quick glance

🔥 Hono — "The new chef who works anywhere"

Hono is a modern web framework built on Web Standards. That means it uses the same Request and Response objects that your browser uses — so it works on Node.js, Cloudflare Workers, Deno, Bun, basically anywhere.

For Sembilu:

  • Built-in WebSocket support — the kitchen screen updates instantly when a waiter sends an order
  • Built-in JWT auth — staff log in, get a token, done
  • RPC mode — your frontend can call the backend and TypeScript checks that you're passing the right data, like a type-checked phone line between waiter and kitchen
  • Has a Zod validator built in — Zod is a library that checks "is this really a number?" before saving to the database
  • ~31k GitHub stars, ~53M weekly npm downloads

Learning curve: Low. Routes look similar to Express. Good docs.

📦 Express — "The veteran everyone recommends"

Express is the oldest and most popular Node.js framework. It's been around since 2010. If you Google "how to build a Node.js API," 9 out of 10 results will use Express.

For Sembilu:

  • Huge community — any problem you hit, someone has solved it before
  • Nothing built-in — it's "unopinionated," meaning you bring your own tools for WebSocket, auth, validation, etc.
  • WebSocket requires adding socket.io or ws separately
  • TypeScript is via @types/express — separate package, not native
  • No built-in way to share types between frontend and backend
Think of it like a kitchen with nothing but a stove and a knife. You can build anything, but you have to bring every other tool yourself. Great if you want total control. More work if you want things like WebSocket or auth to "just work."

Learning curve: Low. Minimal API, endless tutorials.

🏎️ Fastify — "The performance-focused kitchen"

Fastify cares about speed. It claims up to 30k requests per second. It also has a powerful plugin system — plugins are official packages (297+ of them) that snap in cleanly.

For Sembilu:

  • Official @fastify/websocket plugin for real-time
  • Official JWT, CORS, auth plugins
  • Uses JSON Schema for validation — you describe your data in a special format and it validates automatically (fast, but requires learning JSON Schema)
  • Type Providers for type safety (TypeBox, Zod)
  • ~36k GitHub stars, ~10M weekly npm downloads

Learning curve: Medium. JSON Schema and the plugin system take some getting used to.

🔗 tRPC — "The mind-reading phone line"

tRPC isn't a full web framework — it's a layer that sits inside another framework (Express, Fastify, or its own standalone server). Its superpower: the frontend knows exactly what the backend expects.

Normally you write an API endpoint, then manually type out the same thing on the frontend. tRPC does this automatically. Change the backend, and TypeScript yells at you on the frontend instantly.

For Sembilu:

  • Maximum type safety — if you rename a field on the server, the client code breaks at build time, not at runtime
  • Built-in subscriptions via WebSocket or SSE (Server-Sent Events) — perfect for live KDS updates
  • Uses Zod for validation
  • Needs a host framework (standalone or Express/Fastify) — it's not a replacement for one
  • Best in a monorepo (one repo containing both frontend and backend code)
  • ~40k GitHub stars, ~4.7M weekly npm downloads

Learning curve: Medium. Requires understanding TypeScript generics and Zod. Excellent docs.

What does this mean for Sembilu?

Our restaurant system needs three things that narrow the choice:

  1. Real-time WebSocket — kitchen display, live order tracking. Express has none built-in.
  2. Type safety — we want the frontend and backend to speak the same language without manual work. Express has none.
  3. Auth — staff login. All four can do this, but Hono and Fastify have it built-in.

My recommendation stays: Hono

Express is too bare — you'll spend more time adding things than building features. Fastify is great but learning JSON Schema adds friction. tRPC is beautiful but assumes a monorepo and adds complexity.

Hono gives you WebSocket + JWT + Zod validation + RPC type sharing out of the box, with a learning curve as low as Express. It's the best balance for this project.
