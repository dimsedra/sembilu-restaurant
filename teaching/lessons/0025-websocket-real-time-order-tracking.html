Lesson 25: WebSockets for Real-Time Order Tracking

Lesson 0025 · Sembilu Operating System · Informed Knowledge & Context

In this lesson, we learn about WebSockets — the real-time communication technology that allows Chef Budi's kitchen actions on the KDS screen to push live status updates to a customer's phone at Table 4.

🏛️ 1. Informed Context: Why WebSockets at Sembilu?

The Problem: Traditional HTTP Polling

Imagine a customer sitting at Table 4 watching their phone tracking screen. They want to know when their Ayam Goreng changes from pending ➔ cooking ➔ done.

With traditional HTTP, the browser must ask the server repeatedly every 2 seconds:

  • 📱 Phone: "Is the food cooking yet?" ➔ 🖥️ Server: "No."
  • 📱 Phone: "Is the food cooking yet?" ➔ 🖥️ Server: "No."
  • 📱 Phone: "Is the food cooking yet?" ➔ 🖥️ Server: "Yes! It's cooking now!"

The Problem: 95% of requests return "No", wasting phone battery, network data, and overloading the Express server with thousands of useless HTTP requests.

The Solution: WebSockets (Persistent Push Pipe)

Instead of asking repeatedly, the customer's phone opens one single persistent connection to the server.

  • 1️⃣ Phone connects once over ws://localhost:3001.
  • 2️⃣ The server holds the connection open in memory.
  • 3️⃣ When Chef Budi taps "Start Cooking" on the KDS screen (T7), the Express server immediately pushes a status event to Table 4's phone: { orderId: 4, status: "cooking" }!

📊 HTTP Polling vs. WebSockets

Feature HTTP Polling WebSockets
Connection Model Request ➔ Response (Closed after each call) Persistent Open Connection (Stays open)
Communication Direction One-way (Client must ask first) Bi-directional / Full-Duplex (Both can send)
Data Overhead High (HTTP headers sent every 2 seconds) Low (Lightweight data frames, zero headers)
Best Used For Fetching static menus, placing orders Live order tracking, chat, real-time KDS

📚 2. Beginner's Glossary

WebSocket
A network protocol providing full-duplex, real-time communication channels over a single TCP connection.
HTTP Handshake
The initial HTTP request where the client asks the server: "Can we upgrade this connection to a WebSocket?" (HTTP status 101 Switching Protocols).
Full-Duplex
Communication where data can flow in both directions at the same time (client ➔ server AND server ➔ client).
Event Emitter
A programming pattern where the server broadcasts events (e.g. "order:updated") to connected listeners.

🧩 3. Informed Knowledge: How WebSockets Work in Code

1. Server-Side WebSocket Setup (`ws` library)

import { WebSocketServer, WebSocket } from "ws"
import http from "http"
import app from "./index"

const server = http.createServer(app)
const wss = new WebSocketServer({ server })

// Store connected clients
const clients = new Set()

wss.on("connection", (socket) => {
  clients.add(socket)
  console.log("📱 Customer connected for order tracking!")

  socket.on("close", () => {
    clients.delete(socket)
  })
})

// Function to broadcast order updates to all connected screens
export function broadcastOrderUpdate(orderId: number, status: string) {
  const message = JSON.stringify({ event: "order_updated", orderId, status })
  for (const client of clients) {
    if (client.readyState === WebSocket.OPEN) {
      client.send(message)
    }
  }
}
Line-by-line Breakdown:
  • const wss = new WebSocketServer({ server }): Attaches a WebSocket listener to our HTTP server on port 3001.
  • clients.add(socket): Remembers active browser connections in a Set.
  • broadcastOrderUpdate(): Loops through active connections and sends instant JSON updates when Chef Budi updates dish status!
