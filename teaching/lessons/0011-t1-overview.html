Layer 1: The Migration

File: server/migrations/20260730-create-dishes.ts

exports.up = (knex) => knex.schema.createTable("dishes", (t) => {
  t.increments("id")           // ← auto-incrementing primary key
  t.string("name")             // ← dish name
  t.text("description")        // ← longer text
  t.integer("price")           // ← number, stored in ribuan (89 = Rp 89.000)
  t.string("tag").nullable()   // ← optional badge like "Unggulan"
  t.string("aksara_no")        // ← Javanese numeral for display only
  t.integer("branch_id")       // ← foreign key to branches table
    .references("id")
    .inTable("branches")
    .notNullable()
  t.timestamps()               // ← created_at + updated_at
})

What you said about IDs: The id column is a latin auto-incrementing number (1, 2, 3...). The aksara_no is the Javanese numeral (꧑, ꧒, ꧓...) for display only. The database never uses aksara for lookups.

After creating the table, the migration seeds it with 7 dishes from src/data.ts, all assigned to branch 1 (Tegal).

Layer 2: The API Route

File: server/routes/dishes.ts

// GET /api/dishes — returns all dishes
router.get("/", async (req, res) => {
  const query = db("dishes")
  if (req.query.branch_id) {
    query.where("branch_id", Number(req.query.branch_id))
  }
  const dishes = await query.orderBy("id")
  res.json(dishes)
})

// GET /api/dishes/:id — returns one dish or 404
router.get("/:id", async (req, res) => {
  const dish = await db("dishes").where("id", Number(req.params.id)).first()
  if (!dish) {
    res.status(404).json({ error: "Dish not found" })
    return
  }
  res.json(dish)
})

Two endpoints, both use knex to build SQL queries:

  • knex('dishes') = SELECT * FROM dishes
  • .where('branch_id', 1) = WHERE branch_id = 1
  • .first() = LIMIT 1 (returns a single object, not an array)

These are registered in server/index.ts with:

app.use("/api/dishes", dishesRouter)

So every request to /api/dishes... gets routed to this file.

Layer 3: The Test

File: server/routes/dishes.test.ts

import request from "supertest"
import app from "../index"

it("returns all dishes", async () => {
  const res = await request(app).get("/api/dishes")
  expect(res.status).toBe(200)
  expect(res.body.length).toBe(7)    // ← 7 seeded dishes
  expect(res.body[0]).toHaveProperty("name")
  expect(res.body[0]).toHaveProperty("price")
})

We use Supertest to make fake HTTP requests — no real server port needed. The test sends a GET, and Supertest feeds it directly into the Express app in memory. If the route is missing, the query is wrong, or the response format changes, the test fails.

Why test this way? One test covers the route definition, the database query, the response format, and the error handling. If we refactor the route internals later but keep the same response, the test still passes — that's testing behavior, not implementation.

Layer 4: The Frontend Page

Two files changed on the frontend:

src/pages/MenuPage.tsx — a new full-page view at /menu. It fetches from /api/dishes on mount and renders the dishes in the Candlelit Heirloom design (Fraunces headings, emas accents, aksara numerals).

src/components/Menu.tsx — the original homepage section. Previously it imported signatureDishes from data.ts. Now it fetches from /api/dishes like the full page does.

The fetch is simple:

useEffect(() => {
  fetch("/api/dishes")
    .then(r => r.json())
    .then(setDishes)
}, [])

In development, this request goes to localhost:5173/api/dishes (the Vite dev server), and Vite's proxy forwards it to Express at localhost:3001/api/dishes. This is configured in vite.config.ts:

server: { proxy: { "/api": { target: "http://localhost:3001" } } }

Without the proxy, the frontend would have to use the full URL http://localhost:3001/api/dishes, which would break in production and cause CORS issues. The proxy makes it seamless.

The key takeaway: A vertical slice means you build one complete path from database all the way to the browser. Not "all the database tables first" then "all the APIs" then "all the pages." One feature, end to end, every time.
