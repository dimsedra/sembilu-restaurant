Zustand: The Kitchen Whiteboard

A way for different parts of your app to share information — explained with a restaurant kitchen.

🍽️ Imagine the Sembilu kitchen. The chef, the waiters, and the cashier all need to know what's happening. A waiter marks an order, the chef sees it. The cashier closes the bill, the waiter knows not to serve. Everyone stays in sync.

That's what Zustand does for your app. It's a whiteboard in the middle of the kitchen that anyone can read from or write to — without having to ask for permission.

The old way: passing notes

Before Zustand, if two far-apart parts of your app needed to share information (like a cart item and a checkout button), you had to pass that information through every layer between them. Like a waiter who has to tell the manager, who tells the sous chef, who finally tells the line cook. Lots of middlemen.

In React terms, that middleman is called Context. It works, but every time you add shared information, you add another layer of middlemen. Your code starts looking like a pyramid.

Zustand: just a whiteboard

With Zustand, you just put up a whiteboard and everyone reads from it directly. No managers. No middlemen. Just the information, right where everyone can see it.

Here's what a whiteboard looks like in code:

import { create } from 'zustand'

// Put up a whiteboard named 'useCart'
const useCart = create((set) => ({
  // What's on the board right now:
  items: [],

  // Actions people can take:
  addItem: (item) =>
    set((state) => ({ items: [...state.items, item] })),

  clearCart: () => set({ items: [] }),
}))

Now any component in your app can read the cart:

function CartIcon() {
  // "Read just the 'items' part of the whiteboard"
  const count = useCart((state) => state.items.length)

  return <span>Cart ({count})</span>
}

function AddToCartButton() {
  const addItem = useCart((state) => state.addItem)

  return <button onClick={addItem}>Add to cart</button>
}

That's it. Two different components, reading from the same whiteboard, no middlemen. The CartIcon only cares about the count. The AddToCartButton only cares about the action. They each take exactly what they need.

So why not always use it?

Think of it like this: If only one waiter needs to know the daily special, just tell that waiter. That's useState.

If the whole kitchen needs to know an order, put it on the whiteboard. That's Zustand.

Don't put something on the whiteboard if only one person needs it.

For Sembilu:

  • Cart items → whiteboard (Zustand). Many components need this (menu, cart icon, checkout).
  • Reservation form fields → probably local. Only the Reserve section touches date/time/pax.
  • 9 sambals menu data → already just imported from data.ts. No state needed.

One thing to try: Open src/components/Reserve.tsx and find the useState lines. There's cart state there (item quantities). Imagine moving that to the whiteboard instead.
