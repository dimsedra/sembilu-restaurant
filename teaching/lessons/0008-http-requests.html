HTTP: The Waiter Between Frontend and Backend

Lesson 8 · How your React app talks to your Express server.

🙋 Imagine you're sitting at a Sembilu table. You want Ikan Bakar Pantura. You don't walk into the kitchen and cook it yourself. You tell the waiter: "I want the Ikan Bakar." The waiter goes to the kitchen, tells the chef, and comes back with your food.

That's what HTTP is. Your React app (the customer) makes a request to the Express server (the waiter). The server processes it, talks to the database (the chef) if needed, and sends back a response.

A request has 3 parts

1. Method (the verb)

What do you want to do?

MethodWhat it meansRestaurant analogy
GETGive me data"What's on the menu?"
POSTCreate something new"I'd like to place an order"
PUTReplace something"Change my entire order"
PATCHUpdate part of something"Make the sambal extra pedas"
DELETERemove something"Cancel my order"

2. URL (the what)

Which thing are you talking about?

GET /api/branches        → "Give me all branches"
GET /api/branches/1      → "Give me branch number 1 (Tegal)"
POST /api/orders         → "Create a new order"
GET /api/orders/42       → "Give me order number 42"
PATCH /api/orders/42     → "Update order number 42"

The URL is like saying "the Ikan Bakar Pantura" instead of just "food." It specifies which thing.

3. Body (the details)

Extra information, usually in JSON format. Only for methods that change data (POST, PUT, PATCH).

POST /api/orders
Body: {
  "branch_id": 1,
  "table_number": 5,
  "items": [
    { "dish_id": 1, "quantity": 2 },
    { "dish_id": 3, "quantity": 1 }
  ]
}

This is like telling the waiter "table 5 wants two Ikan Bakar and one Gurame."

CodeMeaningRestaurant analogy

Back to the "test seam"

When I said we'll test at the API level, I meant we'll write tests that:

  1. Send a fake HTTP request (like GET /api/branches) to our Express app
  2. Check the status code (is it 200?)
  3. Check the response body (is the data correct?)

We don't need a real browser or a real server port. Supertest creates a fake waiter that talks directly to the Express app in memory. Faster, more reliable, and tests the exact same code that runs in production.

Try it yourself: Open your browser and go to http://localhost:3001/api/health (after running npm run dev:server). You just made a GET request. The { "status": "ok" } you see is the response body. That's all HTTP is — you ask, the server answers.

Try it: Start the server with npm run dev:server, then open http://localhost:3001/api/health in your browser. You just made your first HTTP request.

Confused? This is the foundation of everything — frontend talks to backend, backend talks to database. Make sure it clicks before we move on.
