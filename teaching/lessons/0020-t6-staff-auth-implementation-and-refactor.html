📚 1. Beginner's Code Glossary

Here are the common terms used in backend TypeScript code:

export
Makes a function, variable, or type available for other files to import and use.
interface
A blueprint describing the exact shape an object must have (e.g. what properties it contains).
type guard
A function that inspects data at runtime and confirms to TypeScript: "Yes, this unknown box definitely holds a StaffPayload!"
middleware
A security bouncer function sitting between the incoming web request and your route handler.
req.headers
The envelope sent by the browser or mobile app containing metadata like authorization tokens.
Bearer token
An HTTP authentication format where holding the token string is proof of access (like holding a VIP ticket).
jwt.verify()
A function that checks whether a token's digital signature is genuine and hasn't expired.
next()
The green-light signal in Express telling the server: "Security check passed, proceed to the next step!"

Block 1: Staff Role Blueprint & Interface

export const VALID_STAFF_ROLES = ["waiter", "chef", "manager"] as const
export type StaffRole = (typeof VALID_STAFF_ROLES)[number]

export interface StaffPayload {
  staff_id: number
  role: StaffRole
  branch_id: number
}
Line-by-Line Explanation:
  • const VALID_STAFF_ROLES = [...] as const: Defines a fixed list of allowed roles. as const tells TypeScript these 3 strings can never change.
  • type StaffRole: Automatically creates a type that means exactly "waiter" | "chef" | "manager".
  • interface StaffPayload: The blueprint of data packed inside Wati's JWT token (her staff ID number, her job role, and her restaurant branch ID).

Block 2: Secret Key Checker (getJwtSecret)

export function getJwtSecret(): string {
  if (process.env.JWT_SECRET) {
    return process.env.JWT_SECRET
  }
  if (process.env.NODE_ENV === "test" || process.env.NODE_ENV === "development" || !process.env.NODE_ENV) {
    return "sembilu-dev-secret"
  }
  throw new Error("JWT_SECRET environment variable is missing.")
}
Line-by-Line Explanation:
  • if (process.env.JWT_SECRET): Checks if a custom secret key was set in our .env file. If found, use it!
  • if (process.env.NODE_ENV === "test" ...): In local dev or automated tests, return "sembilu-dev-secret" so developers can code without extra setup.
  • throw new Error(...): In production, if no secret was provided, STOP immediately! Operating without a secret in production is unsafe.

Block 3: Runtime Type Guard (isValidStaffPayload)

export function isValidStaffPayload(decoded: unknown): decoded is StaffPayload {
  if (typeof decoded !== "object" || decoded === null) {
    return false
  }
  const payload = decoded as Record<string, unknown>
  return (
    typeof payload.staff_id === "number" &&
    Number.isInteger(payload.staff_id) &&
    payload.staff_id > 0 &&
    typeof payload.role === "string" &&
    (VALID_STAFF_ROLES as readonly string[]).includes(payload.role) &&
    typeof payload.branch_id === "number" &&
    Number.isInteger(payload.branch_id) &&
    payload.branch_id > 0
  )
}
Line-by-Line Explanation:
  • decoded: unknown: unknown means data from the outside world that we haven't inspected yet.
  • typeof decoded !== "object" || decoded === null: If the data isn't an object, reject it immediately!
  • Number.isInteger(payload.staff_id) && payload.staff_id > 0: Verifies the staff ID is a positive whole number (e.g. 1, 2).
  • VALID_STAFF_ROLES.includes(payload.role): Verifies the role is genuinely "waiter", "chef", or "manager" (rejecting fake roles like "hacker").

Block 4: Security Bouncer Middleware (requireStaffAuth)

export function requireStaffAuth(req: AuthenticatedRequest, res: Response, next: NextFunction): void {
  const authHeader = req.headers.authorization
  if (!authHeader || !authHeader.startsWith("Bearer ")) {
    res.status(401).json({ error: "Authentication required. Missing Bearer token." })
    return
  }

  const token = authHeader.split(" ")[1]
  try {
    const secret = getJwtSecret()
    const decoded = jwt.verify(token, secret)
    if (!isValidStaffPayload(decoded)) {
      res.status(401).json({ error: "Invalid token payload structure." })
      return
    }
    req.staff = decoded
    next()
  } catch (_err) {
    res.status(401).json({ error: "Invalid or expired token." })
  }
}
Line-by-Line Explanation:
  • const authHeader = req.headers.authorization: Inspects the incoming request envelope for the security header.
  • authHeader.split(" ")[1]: Takes "Bearer eyJhbGci..." and extracts the actual token string after the space.
  • jwt.verify(token, secret): Checks the digital signature against our secret key. If tampered with, it throws an error.
  • req.staff = decoded: Attaches Wati's verified information directly onto the Express request object!
  • next(): Calls Express's green-light function so the request moves forward to the route handler.
