T6 Staff Auth: The What, The Why, and The High-Level How

Lesson 0020 · Sembilu Operating System · Concept First

Before looking at a single line of code, let's step back and understand WHAT T6 is, WHY it exists in the restaurant, and HOW it works conceptually.

🏛️ 1. The WHAT (What is T6?)

T6 (Staff Authentication) is the digital keycard scanner that separates the public dining room (where customers view menus and reserve tables) from the back-of-house staff operations (where waiters place orders, chefs manage the kitchen display, and managers review branch performance).

💡 2. The WHY (Why do we need T6?)

What Happens Without T6? (The Restaurant Nightmare)

  1. Chaos in the Kitchen: A mischievous customer at Table 5 could open developer tools and send an HTTP request to mark another table's order as "Done" or "Cancelled".
  2. Zero Accountability: If an expensive wagyu dish status is deleted, management has no idea who did it — was it Wati (waiter), Budi (chef), or a random stranger?
  3. Multi-Branch Data Leakage: Sembilu operates in Tegal, Slawi, Semarang, and Jakarta. A waiter at Tegal should never see or tamper with kitchen screens in Jakarta!

Why T6 exists: To ensure that every internal action is (1) authenticated (we know who you are), (2) authorized (we know your job role), and (3) branch-scoped (you only touch your branch's data).

🧠 3. The HIGH-LEVEL HOW (The Smartcard & Wristband Analogy)

Here is how the entire system works conceptually in 3 steps:

Step 1: Clocking In (Login)

Wati arrives for her shift at Sembilu Tegal. She types her email (wati@sembilu.com) and password on her waiter tablet. The server checks her password against a secure hash vault.

Step 2: Receiving the Shift Wristband (JWT Token)

If her password matches, the server hands her tablet an 8-hour digital shift wristband (a JWT Token). Sealed inside her wristband is her badge info: [Wati | Waiter | Tegal Branch].

Step 3: Showing the Wristband to the Bouncer (Middleware)

Whenever Wati taps "Serve Dish" or views kitchen orders, her tablet sends her wristband in the request header. The server's bouncer middleware checks the digital signature. If valid, the green light turns on and her request goes through!

📚 4. Beginner's Code Glossary

export
Makes a function or type available for other files to import.
interface
A blueprint describing the exact shape an object must have.
type guard
A function that inspects data at runtime and confirms its exact type to TypeScript.
middleware
A security bouncer function sitting between incoming requests and route handlers.
Bearer token
An HTTP format where holding the token string is proof of access.
next()
The green-light signal telling Express to move to the next handler.

Staff Payload & Role Blueprint

export const VALID_STAFF_ROLES = ["waiter", "chef", "manager"] as const
export type StaffRole = (typeof VALID_STAFF_ROLES)[number]

export interface StaffPayload {
  staff_id: number
  role: StaffRole
  branch_id: number
}
  • const VALID_STAFF_ROLES: List of allowed roles. as const freezes the array values.
  • interface StaffPayload: The 3 fields stamped inside Wati's shift wristband.

Security Bouncer Middleware

export function requireStaffAuth(req: AuthenticatedRequest, res: Response, next: NextFunction): void {
  const authHeader = req.headers.authorization
  if (!authHeader || !authHeader.startsWith("Bearer ")) {
    res.status(401).json({ error: "Authentication required. Missing Bearer token." })
    return
  }

  const token = authHeader.split(" ")[1]
  try {
    const secret = getJwtSecret()
    const decoded = jwt.verify(token, secret)
    if (!isValidStaffPayload(decoded)) {
      res.status(401).json({ error: "Invalid token payload structure." })
      return
    }
    req.staff = decoded
    next()
  } catch (_err) {
    res.status(401).json({ error: "Invalid or expired token." })
  }
}
  • authHeader.split(" ")[1]: Extracts the token string after "Bearer ".
  • jwt.verify(token, secret): Checks the digital signature against our secret key.
  • req.staff = decoded: Attaches Wati's verified identity to Express's request object.
  • next(): Gives the green light to proceed to the route handler.
