1. The Runtime Type Guard (isValidStaffPayload)

This helper in server/routes/staff.ts ensures that untrusted JWT data is validated before our server touches it.

export const VALID_STAFF_ROLES = ["waiter", "chef", "manager"] as const;
export type StaffRole = (typeof VALID_STAFF_ROLES)[number];

export interface StaffPayload {
  staff_id: number;
  role: StaffRole;
  branch_id: number;
}

export function isValidStaffPayload(decoded: unknown): decoded is StaffPayload {
  if (typeof decoded !== "object" || decoded === null) {
    return false;
  }
  const payload = decoded as Record<string, unknown>;
  return (
    typeof payload.staff_id === "number" &&
    Number.isInteger(payload.staff_id) &&
    payload.staff_id > 0 &&
    typeof payload.role === "string" &&
    (VALID_STAFF_ROLES as readonly string[]).includes(payload.role) &&
    typeof payload.branch_id === "number" &&
    Number.isInteger(payload.branch_id) &&
    payload.branch_id > 0
  );
}

Line-by-Line Breakdown:

  • export const VALID_STAFF_ROLES = ["waiter", "chef", "manager"] as const
    What it does: Defines the 3 exact roles allowed in Sembilu. The as const tells TypeScript this array is immutable and its elements are literal string types "waiter" | "chef" | "manager".
  • export type StaffRole = (typeof VALID_STAFF_ROLES)[number]
    What it does: Automatically creates a TypeScript type union equal to "waiter" | "chef" | "manager" directly from the array!
  • decoded is StaffPayload
    What it does: This is a TypeScript type predicate. If this function returns true, TypeScript automatically casts decoded as a StaffPayload everywhere downstream!
  • if (typeof decoded !== "object" || decoded === null) return false
    What it does: Safety check! Rejects primitive values (like numbers or strings) or null to prevent Cannot read properties of null runtime crashes.
  • Number.isInteger(payload.staff_id) && payload.staff_id > 0
    What it does: Ensures the database ID is a valid positive integer (e.g. 1, 42), blocking NaN, Infinity, or negative numbers.
  • VALID_STAFF_ROLES.includes(payload.role)
    What it does: Verifies the role is strictly one of Sembilu's 3 real positions, blocking forged roles like "hacker".

2. The Bouncer Middleware (requireStaffAuth)

This Express middleware protects internal routes from unauthenticated or forged requests.

export function requireStaffAuth(req: AuthenticatedRequest, res: Response, next: NextFunction): void {
  const authHeader = req.headers.authorization;

  if (!authHeader || !authHeader.startsWith("Bearer ")) {
    res.status(401).json({ error: "Authentication required. Missing Bearer token." });
    return;
  }

  const token = authHeader.split(" ")[1];

  try {
    const secret = getJwtSecret();
    const decoded = jwt.verify(token, secret);

    if (!isValidStaffPayload(decoded)) {
      res.status(401).json({ error: "Invalid token payload structure." });
      return;
    }

    req.staff = decoded;
    next();
  } catch (_err) {
    res.status(401).json({ error: "Invalid or expired token." });
  }
}

Line-by-Line Breakdown:

  • const authHeader = req.headers.authorization
    What it does: Reads the HTTP request header sent by the client. Expected format: Authorization: Bearer <jwt-token>.
  • if (!authHeader || !authHeader.startsWith("Bearer "))
    What it does: If no header is attached, or if it doesn't start with "Bearer ", immediately reject with HTTP 401 Unauthorized.
  • const token = authHeader.split(" ")[1]
    What it does: Splits "Bearer eyJhbGci..." by space and extracts just the raw token string eyJhbGci....
  • const decoded = jwt.verify(token, secret)
    What it does: Decodes the token and checks its cryptographic signature. If someone modified even 1 letter in the token, jwt.verify throws an error immediately!
  • req.staff = decoded
    What it does: Attaches the decoded staff object (`{ staff_id, role, branch_id }`) directly to Express's req object so downstream routes know who is calling!
  • next()
    What it does: Express signal to move forward to the actual endpoint handler (e.g. returning staff profile or placing orders).

3. Database Seeding (server/seeds/01_staff.ts)

Decoupled DML file that populates initial development accounts for Wati (waiter), Budi (chef), and Teguh (manager).

export async function seed(knex: Knex): Promise {
  await knex("staff").del();

  const passwordHash = await bcrypt.hash("password123", 10);

  await knex("staff").insert([
    { name: "Wati (Waiter)", email: "wati@sembilu.com", password_hash: passwordHash, role: "waiter", branch_id: 1 },
    { name: "Budi (Chef)", email: "budi@sembilu.com", password_hash: passwordHash, role: "chef", branch_id: 1 },
    { name: "Teguh (Manager)", email: "teguh@sembilu.com", password_hash: passwordHash, role: "manager", branch_id: 1 },
  ]);
}

Line-by-Line Breakdown:

  • await knex("staff").del()
    What it does: Clears existing staff rows first so re-running seeds is idempotent (doesn't fail due to duplicate email constraints).
  • const passwordHash = await bcrypt.hash("password123", 10)
    What it does: Hashes "password123" with a salt cost factor of 10. The salt adds random data to guarantee unique hashes even for identical passwords.
  • await knex("staff").insert([...])
    What it does: Inserts 3 pre-configured staff accounts linked to Branch 1 (Tegal) so you can test all 3 staff roles instantly.
