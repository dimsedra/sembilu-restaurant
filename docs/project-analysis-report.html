1. Identitas Brand & Problem Inti yang Diselesaikan

Visi Kuliner: "Bukan Fusion. Bukan Usang. Hanya Jawa."

Sembilu adalah sistem operasi restoran terpadu (Full-Stack Restaurant Operating System) yang dibangun untuk restoran masakan otentik Jawa berskala heritage dining (berdiri di Tegal sejak 1987, kini berekspansi ke Solo dan Yogyakarta). Proyek ini menolak tren kuliner campur aduk dan fokus menjaga warisan bumbu pusaka Nusantara serta 9 varian sambal khas daerah.

Problem Fragmentasi Operasional

  • Sistem Terpisah: Website promosi, aplikasi reservasi, printer kasir, dan kertas tiket dapur berada di platform berbeda tanpa sinkronisasi.
  • Kekacauan Dapur (Ticket Rail): Koki kesulitan menghitung total porsi masakan yang sama untuk dimasak sekaligus (batch cooking).
  • Ketiadaan Visibilitas Tamu: Pelanggan di meja tidak memiliki kejelasan status makanan setelah memesan.
  • Konflik Meja Reservasi: Tamu walk-in sering menduduki meja yang telah dibooking tanpa validasi otomatis.

Solusi Terpadu Sembilu

  • Single-Repo Dual-Audience: Customer Realm (Front-of-House) dan Staff Realm (Back-of-House) berada dalam satu monorepo terpadu.
  • Kitchen Display System (KDS): Tablet dapur dengan rail FIFO dan All-Day batch aggregator untuk efisiensi koki.
  • Live Order Tracking: Pelacakan pesanan real-time via WebSocket dengan timeline 4 tahap bagi tamu.
  • Gatekeeper & Grace Period: Validasi otomatis meja walk-in vs reservasi dengan toleransi waktu ±15 menit.

3. Mental Model Rekayasa Perangkat Lunak

1. Explicit Architecture over Framework Magic

Menolak framework all-in-one atau ORM hitam yang menyembunyikan query SQL. Menggunakan Express 5 dan Knex.js secara eksplisit sehingga siklus HTTP, validasi, dan SQL query sepenuhnya dapat diprediksi dan dikontrol.

2. Deterministic State Machine (FSM)

Item dapur mengikuti alur satu arah yang terikat: pending → cooking → done. Sistem menolak transisi ilegal atau regresi status (misal: masakan yang sudah done tidak bisa kembali ke pending).

3. Parent-Child Derived State

Status pesanan induk (order) tidak disimpan secara terpisah yang rentan inkonsistensi, melainkan diagregasikan dari item-item anaknya: saat item pertama dimasak, order menjadi cooking; saat seluruh item selesai, order otomatis menjadi done.

4. Temporal Windows & Buffer Tolerances

Validasi waktu reservasi dunia nyata mengakomodasi kedatangan lebih awal atau keterlambatan tamu dengan rentang toleransi ±15 menit sebelum dan sesudah jadwal booking.

5. Multi-Tenant Branch Scoping

Token JWT menyematkan { staff_id, role, branch_id }. Waiter dan Chef secara otomatis terkunci pada cabang mereka sendiri di level query SQL, sedangkan Manager memiliki hak multi-cabang.

6. Physical Ergonomics for Kitchen

UI tablet dapur dirancang untuk lingkungan kerja bertemperatur tinggi: target sentuh minimal 44px, elapsed timer berbasis urgensi warna (hijau <10m, amber 10-20m, merah berkedip >20m), dan audio lonceng disintesis langsung via Web Audio API (0 aset eksternal).

Mekanika Propagasi Status Induk (server/routes/staff-orders.ts) 
// Update single line item with deterministic transition guard
const currentItem = await db('order_items').where({ id: itemId, order_id: orderId }).first();
if (!VALID_ITEM_TRANSITIONS[currentItem.status]?.includes(newStatus)) {
  return res.status(400).json({ error: `Invalid transition from ${currentItem.status} to ${newStatus}` });
}

await db('order_items').where({ id: itemId }).update({ status: newStatus });

// Propagate status to parent order
const allItems = await db('order_items').where({ order_id: orderId });
const allDone = allItems.every(i => i.status === 'done' || i.status === 'served');
const anyCooking = allItems.some(i => i.status === 'cooking' || i.status === 'done');

let newOrderStatus = order.status;
if (allDone) {
  newOrderStatus = 'done';
} else if (anyCooking && order.status === 'pending') {
  newOrderStatus = 'cooking';
}

if (newOrderStatus !== order.status) {
  await db('orders').where({ id: orderId }).update({ status: newOrderStatus });
}

Logika & Sebab Akibat (Input → Proses → Output):

  • Input: Permintaan perubahan status line item dari staff tablet (itemId, newStatus).
  • Validasi Transisi: Memeriksa status saat ini terhadap VALID_ITEM_TRANSITIONS. Mencegah status melompat tidak wajar atau kembali mundur.
  • Agregasi Otomatis: Mengkueri seluruh item saudara pada pesanan yang sama. Jika semua item sudah done, status order induk dinaikkan menjadi done. Jika item pertama mulai cooking, status order naik dari pending ke cooking.
  • Output: Data database konsisten seketika, dilanjutkan dengan broadcast pesan WebSocket ke seluruh client terhubung.
Sintesis Audio Lonceng Dapur Tanpa Aset Eksternal (src/utils/sound.ts) 
export function playKitchenBell(muted = false) {
  if (muted || typeof window === 'undefined') return;
  const AudioCtx = window.AudioContext || (window as unknown as { webkitAudioContext: typeof AudioContext }).webkitAudioContext;
  if (!AudioCtx) return;

  const ctx = new AudioCtx();
  const now = ctx.currentTime;

  // Tone 1: High fundamental brass chime
  const osc1 = ctx.createOscillator();
  const gain1 = ctx.createGain();
  osc1.type = 'sine';
  osc1.frequency.setValueAtTime(880, now);
  osc1.frequency.exponentialRampToValueAtTime(440, now + 0.8);
  gain1.gain.setValueAtTime(0.3, now);
  gain1.gain.exponentialRampToValueAtTime(0.001, now + 0.8);

  // Tone 2: Harmonic shimmer
  const osc2 = ctx.createOscillator();
  const gain2 = ctx.createGain();
  osc2.type = 'triangle';
  osc2.frequency.setValueAtTime(1320, now);
  osc2.frequency.exponentialRampToValueAtTime(660, now + 0.5);
  gain2.gain.setValueAtTime(0.15, now);
  gain2.gain.exponentialRampToValueAtTime(0.001, now + 0.5);

  osc1.connect(gain1); gain1.connect(ctx.destination);
  osc2.connect(gain2); gain2.connect(ctx.destination);

  osc1.start(now); osc1.stop(now + 0.85);
  osc2.start(now); osc2.stop(now + 0.55);
}

Logika & Keunggulan Rekayasa:

  • Zero Asset Overhead: Suara dihasilkan secara prosedural menggunakan osilator peramban (sine wave 880Hz ± harmonik triangle wave 1320Hz dengan exponential gain decay).
  • Ketahanan Jaringan: Audio tetap berbunyi seketika tanpa latency download file audio eksternal (no HTTP audio request).
  • Resilience: Dilengkapi penanganan fallback jika AudioContext tidak didukung atau sedang dalam kondisi muted.
